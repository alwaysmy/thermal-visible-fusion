# Android 接入边界和分阶段验证

## 架构

Camera2 可见光采集和厂商 USB 热像采集分别进入时间配对层。两路输出必须带真实格式、尺寸、裁剪、方向、相机身份、时钟来源和帧有效状态。配对层把稳定、同平面的靶标帧交给自动标定；质量检查通过后保存配准记录。显示层只变换可见光，将它映射到原生热像网格。测温层只读厂商原始帧/温度矩阵。

Python 是算法参考实现。Android 端后续可以采用 OpenCV Android/C++ 实现同样数学和门槛，先对相同输入导出结果做数值一致性测试。当前 Kotlin 文件只有 SDK 中立的接口草案，没有 Android 构建配置或 SDK 实现。

## 收到厂商文件后先确认

1. 准确型号、USB VID/PID、序列号或稳定设备标识、固件版本
2. Android SDK/AAR/JAR/SO、API 文档、官方源码示例、官方 demo APK；APK 只能辅助静态核对，不能替代完整 SDK
3. 支持的 ABI、最低 Android 版本、target SDK、USB 权限/插拔/重连流程、授权限制
4. 帧回调真正提供什么：原始辐射计数、温度矩阵、仅 YUV/RGB 预览，还是多种接口
5. 原始数据类型、字节序、行跨度、元数据/帧头、坏点/无效像素掩码、帧序号和缓冲区生命周期
6. 温度单位、比例/偏置/SDK 转换 API、范围切换、发射率、反射温度等参数；不知道的字段不得猜测
7. NUC/快门校正状态、过热/离线状态和丢帧标记
8. 热像时间戳是曝光/读出/设备时钟还是主机回调时刻；与 Camera2 时钟的关系必须测量和明确

手机侧还需手机型号、Android 版本、目标后置 camera ID/physical camera ID、两路同时采集能力。须防止自动镜头切换、连续自动对焦、数字变焦、EIS/OIS 引起的投影变化。若不能关闭或准确补偿，会影响是否能够安全复用标定。

不能把 RGB 伪彩图反算为真实温度。若 SDK 只有预览图，应明确降级成几何显示叠加；测温功能不能伪造。原始帧和温度矩阵仍须由 SDK 支持才可接入当前数据契约。

## 最小第一版功能

1. USB 热像实时预览和断开重连；保留纯红外模式
2. 后置相机固定选择与稳定采集；可见光失效不阻断有效纯红外显示
3. 同平面靶检测，显示标记数量、覆盖区域和验证误差
4. 至少一组新的独立验证帧，误差超门槛不保存为可用融合配置
5. 配准配置绑定物理结构和采集管线，重装镜头/换垫圈/改变支架/距离后重标定
6. 可见光边缘强度/透明度调整；热像与融合一键切换
7. 失效时明确提示原因；不存在“即使失败也强行拉齐”的路径
8. 导出原始热帧、温度矩阵、两路原始图和完整元数据用于诊断；要导出哪些文件由用户决定

## 质量门槛

离线默认设置：至少 12 对角点；有效点凸包覆盖各图至少 20%；RANSAC 2 热像素；至少 75% 内点；独立验证 P95 不高于 1.5 热像素、最大不高于 2.5 热像素；时间差不高于 40 ms；显示帧最长 150 ms。

这些值没有经过目标硬件验证。尤其 40 ms 不等于运动场景能精确配准：固定 PCB/固定支架是前提；移动场景应收紧预算或停用融合。真实验收应先基于最小封装尺寸确定允许热像素误差，再倒推出门槛。

几何错误、配置过期或可见光不同步时，可以显示最新且有效的纯红外；若热像本身无效或过时，只能显示“等待有效热帧”，不能把旧图伪装成实时数据。

## 接入完成的验收条件

- SDK 可正常采集，原始帧尺寸/字节序/帧头经过实测核对
- 同步时钟与实际延迟有证据，丢帧/缓冲区覆盖不造成错配
- 真实靶在两路都可检测，独立帧和不同靶位置的误差满足真实门槛
- 板面位置/四角/边界/不同元件高度的误差分别评估
- 插拔、NUC、前后台切换、屏幕旋转、相机重启、镜头切换不误用旧配置
- 切换融合模式前后原始热帧和温度矩阵逐字节/逐值相同
- 最小封装的热定位有效性由真实热靶/已知发热点验证，不能用渲染效果替代
